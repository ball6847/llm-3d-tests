# AGENTS.md

Repo-specific rules for the 3D scene bench. Cross-project habits live in
`~/.pi/agent/AGENTS.md`.

## What this repo is

One prompt was sent to many LLM models. Each model returned a standalone
HTML file with a Three.js scene. A collection owns one prompt and one folder
of results:

| slug | label | folder |
|---|---|---|
| `aurora-torus` | Aurora torus | `collections/aurora-torus/` |
| `aurora-torus-with-control` | Aurora torus with control | `collections/aurora-torus-with-control/` |

`collections.js` holds that list. The slug is the key used everywhere: the
manifest key, the prompts file key, the thumbnail prefix, the `?v=` URL value,
and the folder name under `collections/`.

- The result folders are the source of truth. The sync script never edits or
  deletes result HTML files.
- The key for one result is collection plus model slug, not the slug alone.
  `agnes-3.0-flash` and `tiel-coder-q3` were run for both collections.

## Rules

- Never hand-edit `manifest.js`. It is generated by `tools/sync-collection.mjs`
  from the files on disk. Change the files, then re-run the sync.
- After adding, renaming, or deleting a result file, run
  `node tools/sync-collection.mjs`. Start with `--dry-run` when the change is
  not obviously safe. `--force` re-captures every thumbnail, `--prune` deletes
  thumbnails whose result file is gone.
- Result filenames are lowercase and carry no version suffix. A model name is
  the filename without `.html`, and it must match the card label.
- `prompts.js` holds one prompt string per collection slug. `app.js` reads them
  from `window.PROMPTS`. The sync script does not touch this file.
- The rendered scenes are shown as-is. Do not restyle, reformat, or inject
  styles into anything under `collections/`.
- To add a collection: add an entry to `collections.js`, create
  `collections/<slug>/`, add the prompt string to `prompts.js`, then run the
  sync.

## Running it

No build step. Serve the folder with `python3 -m http.server` and open
`index.html`.

The live site is <https://ball6847.github.io/llm-3d-tests/>, served by GitHub
Pages from the `main` branch. Push to `main` and the site rebuilds. The repo is
`ball6847/llm-3d-tests`.

- Over http, the viewer swaps models without reloading the page and Back works.
- Over `file://`, Chrome treats each local file as a separate opaque origin,
  so a model switch becomes a normal navigation. Back and deep links still work.

## Dependencies

The capture tools need Node, Playwright, and a Chrome binary. They resolve
Playwright via `require('playwright')`, then fall back to a neighboring
project's copy. `CHROME_PATH` points at a different browser; `THUMB_W` and
`THUMB_H` change the capture size.

Scenes fetch Three.js from a CDN, so capture needs a network connection.

## Skills

- `.agents/skills/sync-bench/` keeps the grid, the manifest, and the
  thumbnails in step with the files on disk. Use it instead of editing
  `manifest.js`.
- `.agents/skills/web-design-guidelines/`, `.agents/skills/ui-ux-pro-max/`,
  and `.agents/skills/better-layout/` apply to any change to `index.html`,
  `view.html`, `app.css`, or `app.js`.

## Verification

Open the pages and look at them before reporting a change done. Check that the
model count matches the number of files in the selected collection, that a new
card shows a real thumbnail, that clicking a card opens the right scene, and
that the viewer's collection and model selects list the new model.
